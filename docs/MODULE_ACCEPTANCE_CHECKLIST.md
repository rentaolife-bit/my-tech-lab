## 0. 使用说明（重要）

1. **不能仅凭代码存在判定通过**。每一项必须填写"验收方法"实际执行的动作与"证据记录"的实际结果（命令输出、测量值、设备与日期、截图路径等）。
2. **三态图例**：`PASS`＝通过；`FAIL`＝不通过；`N/A`＝不适用。`N/A` 必须在证据或备注栏写明原因，不得当作 PASS；不适用项不计入适用项的通过率。
3. **适用组别**：组 E（AI 请求）仅对带 AI 工作流的模块适用；组 D（Data Center）应根据模块是否拥有需纳入 Data Center 管理的数据决定——`dataOwnership=shared` / `none`（不拥有独立业务数据）的模块可标记 `N/A`。此判定不改变 Data Center 对实际拥有业务数据的模块所要求的数据保护原则。
4. 标记含义与规范一致：**【已验证】**= Task Manager 与 Notes 已验证实践，**【推荐实践】**= 可调整，**【待验证】**= 尚未定型。
5. 结论为"通过"的模块才可进入"规范推广"；任何一项"不通过"需回退修复并复验。
